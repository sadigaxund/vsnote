## 4. How to operate the new machinery

| Task | Command |
|---|---|
| Build for e2e/demo | `npm run build:demo` |
| Full e2e suite | `VSNOTE_SHARE_PROXY_TARGET=http://127.0.0.1:8788 npm run test:e2e` |
| UI audit (reflow/contrast/vision captures) | build:demo, then `VSNOTE_UI_AUDIT=1 npx playwright test tests/e2e/ui-audit.spec.ts` |
| Refresh vendored skill refs | `npm run skills:update` (pinned) / `:latest` (float) |
| One-time react-doctor audit | `npx react-doctor@latest --no-telemetry --project src` |

Gotchas learned the hard way (all documented in ARCHITECTURE.md Deviations):
- plain `npm run build` produces the NON-demo vault → ~18/20 e2e specs fail
  on missing files; use `build:demo` for anything e2e-shaped.
- a stale uvicorn holding 8788 green-lights the wrong backend; the squatter
  guard now fails loudly, but kill strays before debugging sign-in failures.
- new unit tests must not transitively import `src/fs/client.ts`
  (fsIsolation guard) — split pure helpers into their own module.
- em-dashes are banned in ALL string literals (uiCopyEmDash guard).
