- **Never `pkill -f uvicorn`.** That pattern matches your own shell's command

**Two editor defects** found during review and fixed in `ee14f44`. Both are
worth knowing about because the causes recur:

1. **Selection misalignment in live preview.** With CM6's `drawSelection`, the
   `.cm-selectionLayer` is a SIBLING of `.cm-content` inside `.cm-scroller`, so
   it does not inherit horizontal padding set on `.cm-content`. The first
   selected line is drawn from the measured cursor rect (at the text) and every
   continuation from the layer's own left edge. Any horizontal inset must live
   on `.cm-scroller`, never on `.cm-content` or `.cm-line`. Note also that
   atomic-editor injects its stylesheet at RUNTIME, so an equal-specificity
   override in `index.css` loses on source order.
2. **The active line hid the selection.** `.cm-activeLine` is a background on
   the line element, while the selection is painted underneath it, so an opaque
   active-line colour covers the selection on exactly the caret's line. Keep it
   translucent.

## 4. Security properties worth not breaking

These are load-bearing, not incidental:

1. **Scripts never run on the main thread.** There is no fallback path. Keep
   `@markii/lua` out of every main-thread module: `scriptIsolate.ts` may hold
   only `import type`. A value import there pulls the whole Lua VM plus wasmoon
   into the boot chunk (this regressed once and was caught by a bundle grep).
2. **The watchdog is not redundant.** `@markii/lua`'s in-VM limits run *between*
   Lua instructions and cannot observe a hang while Lua is suspended in a host
   call. The main-thread `terminate()` is what covers that.
3. **Tier enforcement is at the host.** An `auto`/`scheduled` run never has a
   `post` allowlist or a write-capable `ScriptView` *constructed*, whatever the
   stored grant says. Do not weaken this to "the library refuses it anyway".
4. **Grants are keyed by a content hash** of scripts plus bundled modules plus
   packs, so editing any of them invalidates the grant. That is the point.
5. **Rendering never executes anything.** Both render paths are read-only AST
   walks; widgets render to static markup. `.mkz` and pack loading never run
   third-party JS.
6. **wasmoon must keep its same-origin `wasmUri`.** The default fetches
   `unpkg.com` at runtime, breaking offline (CLAUDE.md rule 3). Guard with:
   `dist/` contains a `.wasm`, the worker chunk exists, `unpkg.com` appears
   *only* inside the worker chunk (an unreachable fallback), and `App-*.js`
   contains no `LuaFactory`/`wasmoon`.

## 5. Known limitations

**Packs cannot render their components.** A `.mkp` pack's only rendering
artifact is a prebuilt third-party `webview.js`. VSNote never executes it: our
directive rendering is plain React on the app origin with no sandbox, so running
it would hand a pack the vault, the lightning-fs IndexedDB and any in-memory
share tokens the instant a note was *opened*, and would break the
"rendering executes nothing" rule outright. A pack that works in VS Code or
Obsidian shows only a labelled placeholder here. Owner-confirmed 2026-09-06;
permanent while no component sandbox exists. Upstream ask recorded as MK-15.

**No `.mkz` browsing or editing surface.** A bundle is picked up by sibling-path
convention (`note.mk.md` -> `note.mkz`) and loaded into a run. There is no
bundle browser and no write-back wiring.

**No auto or scheduled trigger.** The host-side tier gate is built and tested,
but nothing calls `runScripts` with a non-manual trigger, so no
"run automatically" control ships. A dead toggle was removed rather than shipped.

**Pack attribute-value completion is absent.** `componentCatalog.ts` was
re-vendored untrimmed so directive *names* and hover are pack-aware, but
`completion.ts`/`documentation.ts` keep their `packAttributesFor` trim. Low
value while packs cannot render.

**A `Switch` off-state is nearly invisible in dark themes.** Library defect, no
track-scoped token to retarget, left unpatched rather than force-styled. See
my-you-eye#37 and DESIGN-SPEC item 107.

**`vaultModules` in the grant closure is permanently `{}`.** VSNote has no
vault-wide shared-Lua-module concept, so there is nothing to resolve. A scope
boundary, not a gap.

## 2. What the owner reported, and what was actually wrong

Several reports had a different cause than the symptom suggested. The causes are
worth more than the fixes:

1. **"Custom remote: could not reach the remote host."** Not a draft-vs-store
   bug. github.com's smart-HTTP endpoints send no CORS headers, so the browser
   request died before any status existed and `mapError` honestly called that
   "offline". The 401-then-404 in the server log was the background auto-sync
   against the implicit remote, unrelated to the test. Fixed with an
   authenticated same-origin proxy at `/api/git-proxy/...`, addressed exactly as
   isomorphic-git's own `corsProxify` builds the URL.
2. **"Viewer page looks disabled for a `.py` file."** The publish dialog took a
   `fileKind` prop and never read it, so it disabled nothing; `.py` was simply
   not a modeled `FileKind` at all and fell back to plain text. Both halves are
   fixed, the second by the generic `code` kind.
3. **"Markii sugar does nothing in Rendered mode."** True, and it did nothing in
   Source mode either, for three separate reasons found only by driving the real
   editor: the completion result's `from` covered the `:::` fence, so CodeMirror
   filtered every option away and the popup never opened; accepting an option
   mapped an offset into the inserted text as if it were a document position and
   threw a `RangeError` inside the accept handler; and the Enter binding for
   fence lengthening sits at `Prec.highest` and swallowed the accept. The pure
   helpers were green throughout.
4. **"Arrow keys stall at a code block's edge."** Plain-`.md` fenced code is not
   a block widget at all (atomic-editor decorates it with line classes and
   already reveals the whole block). The only block-replacing widgets in live
   preview are atomic-editor's table and image widgets and our own markii `:::`
   containers, which is where the fix landed.
5. **"Selection covers the margins."** `rectanglesForRange` computes its
   left/right edges once, as `.cm-content`'s box plus a `.cm-line`'s own
   padding, never `.cm-content`'s padding. The reading column's inset therefore
   has to live on `.cm-line`; anywhere else it either undershoots or bleeds.

## 3. Decisions worth keeping

- The owner's Rendered-view settings deliberately do **not** reach visitors. The
  render stays deterministic; the visitor gets their own theme, font-size and
  wrap preferences in browser-local storage instead, and that pill owns wrapping
  for the whole document, so per-block wrap buttons step aside there.
- Aliases and slugs no longer share a format. Aliases are 2 to 64 lowercase
  characters; slugs stay 22 mixed-case. Uppercase in an alias is refused, never
  downcased, because downcasing changes the URL the owner chose.
- The Preview pane is per-tab view state, not a file mode, so the filetype
  registry is untouched and closing the tab closes the preview for free.
- Language coverage is one generic `code` kind resolving per FILE through
  `@codemirror/language-data`, code-split so the boot chunk is unchanged.

## 4. Known gaps left open

- **Cross-column alias/slug race.** Uniqueness is checked case-insensitively by
  query, and same-column races are still backstopped by the DB's own
  case-sensitive unique indexes. A newly generated random slug racing a
  concurrent alias equal to it is not covered; closing it needs a case-folded
  functional index, i.e. a migration this repo does not yet have. Pre-existing,
  not introduced here.
- **The git proxy follows redirects for GET only.** Re-streaming an already
  consumed POST body is not worth the complexity for a case real git hosts do
  not hit. Documented in the code and in ARCHITECTURE.
- **The live-preview reveal hint is once per session and unmeasured.** It passes
  the UI audit, but no one has watched a real writing session with it on.
- **The precache exclusion is structural, not by name.** A chunk is dropped from
  the service worker's precache when every module in it comes from a lazily
  catalogued language package. Forcing those into named chunks with
  `manualChunks` was tried and reverted: it pulled the catalog into the boot
  chunk's static graph and broke the offline cold-start probe.
